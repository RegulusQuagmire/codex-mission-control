# Mission Control Desktop — этап 6

## Запуск

В подготовленной папке проекта откройте `Launch Mission Control.vbs` двойным
щелчком. Он запускает локальный Python без консоли. Установщик и автозапуск Windows
не входят в эту стадию. Для нового окружения: Python 3.12+, Git, установленный
Codex и `python -m pip install -e ".[dev,desktop]"` внутри `.venv`.
Альтернативный установленный entrypoint: `mission-control-desktop`.

Мастер первого запуска предлагает выбрать codex.exe и папку проектов. Проверка
подключения читает авторизацию, доступные модели и лимиты, не запускает inference.
Авторизация выполняется средствами Codex; приложение не запрашивает пароли или токены.

По умолчанию очередь и настройки находятся в
`%LOCALAPPDATA%\CodexMissionControl\missions.sqlite3`, с существующей защитой DPAPI.
Для другой существующей SQLite-очереди доступен параметр `--queue PATH`.
Файлы базы привязаны к Windows-пользователю; перенос не заменяет экспорт/backup
через существующие защищённые средства backend. Ошибки расшифровки не сбрасывают очередь.

## Работа

1. В «Настройки» выберите разрешённую папку проектов и примените доступ.
2. Добавьте миссию: описание, папку, приоритет, зависимости, стратегию и проверки.
   Для проектной задачи явно задайте входные файлы, разрешённые записи и команды
   проверки. Текстовая задача использует существующий validator точного ответа.
3. Просмотрите разрешения конкретной миссии в разделе подтверждений.
4. Запустите очередь. Economy, Balanced и Quality влияют на реальный маршрутизатор;
   Manual допускает только модель и effort из текущего каталога Codex.
5. Проектный результат остановится для отдельного просмотра: исходники, diff,
   команды, ограничения и риск. Просмотрите все разделы и явно подтвердите права.
6. Результаты, проверки, изменения и история доступны из очереди.

После подтверждения код может выполняться с правами вашего пользователя Windows.
Полноценной изоляции ОС нет. Просмотр результата сам по себе не выполняет код.
Согласие относится к конкретному review ID; изменение файлов требует нового просмотра.
Нельзя считать приложение системой автономного ночного исполнения недоверенного кода.

Пауза не теряет очередь. «Продолжить» возобновляет разрешённое выполнение;
ожидание нового approval сохраняется. Остановка проходит через штатную отмену.
При неопределённом исходе обычный Retry заблокирован: изучите журнал и отдельно
подтвердите риск повторения в предусмотренном backend сценарии. `needs_attention`
не становится автоматическим повтором.

## Лимиты и восстановление

Dashboard показывает использованный и оставшийся процент отдельно, реальные окна
и время сброса. «Нет данных» означает отсутствие подтверждённых данных, а не ноль.
Недельная политика остаётся блокирующей при неизвестном недельном окне.
Кнопка подключения обновляет метаданные; GUI не опрашивает App Server постоянно.
Во время работы используются события и существующий Limit Manager.

Очередь, результаты и предпочтения сохраняются backend. Продолжение после запуска
включается отдельно в настройках и сохраняет паузу, approvals и неизвестные исходы.
При недоступности сети или модели ошибка отображается в интерфейсе; ручное
подключение позволяет повторно загрузить каталог без отправки миссии.
Аналитика использует сохранённые попытки, проверки и наблюдения лимитов; оценок
денежной или токенной экономии нет.

## Политика моделей (этап 9)

Откройте Настройки → Политика моделей. Модели и поддерживаемые уровни берутся
из подключённого Codex. Для каждой модели задайте максимальный effort и включите
или выключите «Автовыбор», затем нажмите «Сохранить». Предел действует также
в Manual, при повторе, эскалации и продолжении. Выключение автовыбора сохраняет
возможность явного Manual-выбора в пределах effort.

Кнопка профиля подготавливает Astra Low (`gpt-6-astra`), Sol Medium
(`gpt-6.1-sol`), Luna High (`gpt-6-luna`). Это необязательные личные настройки;
остальные версии не подменяются и не наследуют их автоматически. Сохранённая
недоступная модель остаётся в списке. Изменения не отменяют активный ход.
[Технические границы](../ARCHITECTURE.md).

## Трей и оверлей

По умолчанию закрытие окна сворачивает его в системный трей. Полный выход из меню
трея останавливает управляемый worker и его компоненты. Уведомления не содержат
описания задания. Отключите сворачивание в настройках, если нужен выход по крестику.

Оверлей — отдельное окно, показывающее только миссии Mission Control. Его можно
перемещать за заголовок, раскрывать, закреплять поверх окон и скрывать. Положение
и компактный режим сохраняются. По умолчанию предлагается `Ctrl+Shift+M`;
занятое сочетание вызывает видимую ошибку, а не перехватывается принудительно.
Фильтр «только при активном Codex» использует Windows foreground event и путь
процесса. Для другой установки Codex или недоступного определения отключите
фильтр и используйте ручное отображение. Захвата экрана и записи ввода нет.

## Проверка и границы

Автоматические Qt-тесты используют mock Codex, реальные хранилище и controller:
создание/восстановление очереди, approvals, маршрутизация, пауза/отмена, завершение,
неопределённые исходы, горячая клавиша и масштабы 100/150/200%.
Реальное подключение App Server проверяется отдельно только чтением метаданных.
Физическое перемещение между разными DPI-мониторами и доставка Windows-уведомлений
требуют проверки на целевом рабочем столе. Автозапуска, телеметрии, установщика,
OS sandbox и управления произвольными чатами Codex приложение не добавляет.

## Лимиты и купленные кредиты (этап 10)

В настройках выберите политику кредитов и отдельные резервы 5 часов/неделя
(10–100% оставшегося лимита). Всегда использовать требует явной отметки согласия.
Текущий App Server не предоставляет подтверждённого управления источником оплаты:
все три режима ставят новые запросы на паузу при пороге. Это не гарантирует
отсутствие списаний во время активного хода. Нет покупки или автопополнения.
При неизвестных данных отправка блокируется. Сохранённая миссия ждёт
waiting_credit; продолжение повторно проверяет квоту и ранее выполненные действия.
Подробности: [ограничения безопасности](../SECURITY.md).
